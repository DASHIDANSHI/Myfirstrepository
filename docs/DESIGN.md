# マニフェストPDF抽出・蓄積ツール 設計書

産業廃棄物管理票(紙マニフェスト)のPDFから生成AIで情報を抽出し、Googleスプレッドシートにデータベースとして蓄積するツールの設計書。
最終目的は、東京都「産業廃棄物管理票交付等状況報告書」(様式第三号)の作成を簡易化すること。

- 基盤: Google Apps Script (GAS) Webアプリ
- 参照資料: 東京都環境局「産業廃棄物管理票交付等状況報告書 作成マニュアル(東京都版)」令和8年4月

---

## 1. 東京都マニュアルから導かれる要件

設計の前提として、マニュアルの以下のポイントをシステム要件に反映する。

### 1.1 報告制度の要点(マニュアル p.3)

| 項目 | 内容 | システムへの反映 |
|---|---|---|
| 報告頻度 | 年1回。前年度(4/1〜3/31)交付分を6/30までに報告 | 「交付年月日」から**年度を自動判定**し、年度単位で集計できること |
| 報告対象 | 紙マニフェストを交付した排出事業者。電子マニフェスト分は報告不要 | 本ツールの対象は**紙マニフェストのみ**(電子分はJWNETが報告) |
| とりまとめ | **事業場(排出場所の住所)ごと**に報告書を作成。建設現場等は「都内各工事現場(八王子市を除く)」として1事業場にまとめ可 | **事業場マスター**を持ち、レコードごとに事業場を紐付ける |
| 添付書類 | 不要。報告書のみ提出 | 出力は様式第三号の形式に整形した集計表でよい |

### 1.2 報告書の記載項目(マニュアル p.6〜10 の①〜⑫)

抽出・蓄積すべきデータ項目は、報告書様式の項目に対応させる。

| # | 報告書項目 | マニフェストA票上の位置 | 記載ルール(マニュアルより) |
|---|---|---|---|
| ① | 報告者(住所・氏名・電話) | 排出事業者欄 | 法人名+代表者名。押印不要 → **設定シートから取得(PDF抽出不要)** |
| ② | 事業場の名称・所在地・電話 | 事業場(排出事業場)欄 | マニフェスト記載のとおり → **事業場マスターと照合** |
| ③ | 業種 | (記載なし) | 表1(日本標準産業分類・中分類)から1つ → **事業場マスターに保持** |
| ④ | 産業廃棄物の種類 | 種類チェック欄 | 表2から1つ。詳細は括弧書き。**複数チェックは「(50)その他混合廃棄物」+括弧書きで列挙** |
| ⑤ | 排出量(t) | 数量欄 | t以外(m³, kg, ℓ)は**表3の換算係数でトンに換算** |
| ⑥ | 管理票の交付枚数 | ― | **A票の枚数**をカウント |
| ⑦ | 運搬受託者の許可番号 | 運搬受託者欄 | **下6桁**(全国共通)。自社運搬は**空欄** → マスターから取得 |
| ⑧ | 運搬受託者の氏名又は名称 | 運搬受託者欄 | 自社運搬は「自社運搬」。個人事業主は許可証記載の名称 |
| ⑨ | 運搬先の住所 | 運搬先の事業場(処分事業場)欄 | マニフェスト記載の住所 |
| ⑩ | 処分受託者の許可番号 | 処分受託者欄 | **下6桁**。自治体は**空欄**。有償売却は「有償売却」。再生事業者は「再生事業者番号」。大臣認定は認定番号 → マスターから取得 |
| ⑪ | 処分受託者の氏名又は名称 | 処分受託者欄 | 自社施設間移動は「自社施設」 |
| ⑫ | 処分場所の住所 | 運搬先の事業場欄 | 通常は⑨と同一のため記入不要 |

### 1.3 集計ルール(マニュアル p.6, p.9)

> **④種類・⑧運搬受託者・⑨運搬先・⑪処分受託者の全てが同じ**マニフェストについて、排出量の合計とマニフェスト枚数を1行に記載する。1つでも異なれば別の行に分ける。

→ **DBはマニフェスト1枚=1レコードで蓄積し、報告書生成時に上記4キーでグルーピング集計する。** 蓄積段階で合算しないことで、元データへの遡及・修正・監査が可能になる。

### 1.4 特殊ケース(マニュアル p.7 記載例、p.9〜10)

以下のケースを「特殊区分」としてデータモデルに持たせる。

| ケース | ⑦⑩許可番号欄 | ⑧⑪名称欄 |
|---|---|---|
| 自社運搬 | ⑦空欄 | ⑧「自社運搬」 |
| 処分受託者が自治体(東京都、清掃一部事務組合等) | ⑩空欄 | 自治体名 |
| 有償売却(逆有償で運搬部分のみ廃棄物扱い) | ⑩「有償売却」 | 売却先業者名 |
| 自社施設間の移動(処分委託なし) | ⑩空欄 | ⑪「自社施設」 |
| 再生事業者への委託 | ⑩「再生事業者番号」 | 業者名 |
| 大臣認定業者 | ⑩「大臣認定 平成◯年第◯号」 | 業者名 |

## 2. システム全体像

```
┌──────────────────────────── ユーザー(社内・ブラウザ) ────────────────────────────┐
│  GAS Webアプリ (HTML Service / SPA)                                              │
│  [1] PDFアップロード → [2] AI抽出結果の確認・修正 → [3] 確定保存 → [4] 報告書生成  │
└──────────┬───────────────────────────────────────────────────────────────────┘
           │ google.script.run
┌──────────▼───────────────┐      ┌──────────────────────┐
│  GAS サーバーサイド        │────▶│ 社内生成AI API        │
│  ・Drive保存               │◀────│ (UrlFetchApp / JSON) │
│  ・AI呼び出し・JSON解析     │      └──────────────────────┘
│  ・マスター照合・単位換算   │
│  ・バリデーション・重複検知 │
└──────────┬───────────────┘
┌──────────▼──────────────────────────────────────────────┐
│  Googleスプレッドシート(DB)                               │
│  台帳: マニフェスト台帳 / 取込ログ                          │
│  マスター: 収集運搬業者 / 処分業者 / 廃棄物種類 / 換算係数    │
│           事業場 / 業種 / 設定                             │
│  出力: 報告書(様式第三号レイアウト)                         │
└──────────────────────────────────────────────────────────┘
│  Googleドライブ: 取込PDFの原本保管(台帳からリンク)          │
```

### 処理フロー

1. **アップロード**: ユーザーがWebアプリでPDFを選択(複数可)。GASがDriveの保管フォルダに保存。
2. **AI抽出**: PDFをbase64化して社内生成AI APIへ送信。JSONスキーマを指定した構造化出力で、マニフェストの記載項目(交付番号、交付年月日、事業場、廃棄物種類チェック、数量+単位、運搬受託者、運搬先、処分受託者 等)を抽出。
3. **正規化・照合**(GAS側ロジック):
   - 業者名をマスターと照合(表記ゆれ対応) → **許可番号下6桁をマスターから取得**(AIにPDFの許可番号を読ませるのは補助とし、正はマスター)
   - 廃棄物種類を表2コードにマッピング。複数チェック時は(50)混合廃棄物+括弧書き
   - 数量をトンに換算(換算係数マスター)。元の数量・単位も保持
   - 交付番号による重複チェック、必須項目・値域チェック
4. **確認・修正**: 抽出結果を編集可能なフォームで表示(PDFプレビュー併置)。照合に失敗した項目・信頼度の低い項目は警告表示。ユーザーが修正して確定。
5. **保存**: マニフェスト台帳に1枚=1行で追記。ステータス「確認済」。
6. **報告書生成**: 年度と事業場を指定 → ④⑧⑨⑪でグルーピング集計 → 様式第三号レイアウトのシート(またはExcelエクスポート)を生成。

> **設計方針: AIの抽出は必ず人間の確認を挟む。** 行政報告の元データであるため、全自動保存はしない。確認画面での修正内容はログに残す。

## 3. スプレッドシート設計

### 3.1 台帳シート

#### 「マニフェスト台帳」(1マニフェスト=1行)

| 列 | 項目 | 備考 |
|---|---|---|
| A | レコードID | 自動採番 |
| B | ステータス | 未確認 / 確認済 / 除外 |
| C | 交付年月日 | マニフェスト記載日 |
| D | 年度 | Cから自動判定(4/1〜3/31) |
| E | 交付番号(整理番号) | **重複検知キー** |
| F | 事業場ID | 事業場マスター参照 |
| G | 廃棄物コード | 表2コード |
| H | 廃棄物種類名 | 表2名称 |
| I | 廃棄物詳細(括弧書き) | 例:(廃タイヤ)、混合時の内訳列挙 |
| J | 数量(記載値) | PDF記載のまま |
| K | 単位(記載値) | t / m³ / kg / ℓ |
| L | 換算係数 | 換算係数マスターから |
| M | 排出量(t) | J×L(t記載ならそのまま) |
| N | 運搬業者ID | 収集運搬業者マスター参照(自社運搬は専用ID) |
| O | 運搬受託者名称 | 表示用スナップショット |
| P | 運搬受託者許可番号(下6桁) | マスターから取得 |
| Q | 運搬先の住所 | ⑨ |
| R | 処分業者ID | 処分業者マスター参照 |
| S | 処分受託者名称 | 表示用スナップショット |
| T | 処分受託者許可番号(下6桁) | マスターから取得 |
| U | 処分場所の住所 | ⑫(通常は⑨と同一) |
| V | 特殊区分 | なし / 自社運搬 / 自治体 / 有償売却 / 自社施設 / 再生事業者 / 大臣認定 |
| W | PDFリンク | Drive URL |
| X | 取込日時 / 確認者 | 監査用 |
| Y | AI抽出生データ(JSON) | トラブル時の検証用 |
| Z | 備考 | |

#### 「取込ログ」

取込日時、ファイル名、Drive ID、AI応答時間、成功/失敗、エラー内容、ユーザーによる修正差分。障害調査と精度改善(どの項目が誤読されやすいか)に使う。

### 3.2 マスターシート

#### 「収集運搬業者マスター」(既存・ユーザー準備済み)

| 項目 | 備考 |
|---|---|
| 業者ID | |
| 正式名称 | 許可証記載の名称(個人事業主対応。マニュアル p.9) |
| 別名リスト | 表記ゆれ照合用(カンマ区切り。例: ㈱都庁運輸, トチョウ運輸) |
| 許可番号(全桁) | 例: 13-00-999999 |
| 許可番号下6桁 | 報告書転記用 |
| 許可有効期限 | 期限切れ警告用(推奨追加項目) |
| 有効フラグ | |

#### 「処分業者マスター」(既存・ユーザー準備済み)

収集運搬業者マスターと同じ構成に加えて:

| 追加項目 | 備考 |
|---|---|
| 区分 | 中間処理 / 最終処分 / 自治体 / 再生事業者 / 有償売却先 / 大臣認定 |
| 許可番号代替表記 | 区分に応じ「有償売却」「再生事業者第◯号」「大臣認定◯」等(⑩欄の記載ルール対応) |

#### 「処分事業場マスター」(提案・新規)

処分業者は本社住所と処分場(運搬先)住所が異なり、複数拠点を持つことがあるため、⑨運搬先住所の照合用に業者と分離する。

| 項目 |
|---|
| 事業場ID / 処分業者ID / 事業場名 / 郵便番号 / 住所 |

#### 「廃棄物種類マスター」(表2ベース)

| 項目 | 備考 |
|---|---|
| コード | 表2の番号(例: 廃プラスチック類、(50)その他混合廃棄物 等) |
| 名称 | |
| 区分 | 普通の産業廃棄物 / 特別管理産業廃棄物 |
| マニフェスト欄コード | A票のチェック欄コード(0100系)との対応付け |

> **注意**: 表2(廃棄物の種類)と表3(換算係数)はマニュアル後半(p.13〜16)に掲載されており、今回添付のPDF(前半・p.1〜12)には含まれていない。**マニュアル後半の入手、または東京都環境局サイトからの取得が必要。**

#### 「換算係数マスター」(表3ベース)

| 項目 | 備考 |
|---|---|
| 廃棄物コード | 廃棄物種類マスター参照 |
| 単位 | m³ / kg / ℓ |
| 換算係数(→t) | 表3の参考値。社内実測値がある場合は上書き可とし、出典列を持つ |

#### 「事業場マスター」(提案・新規)

②③の記入と事業場ごとの報告書分割に必須。

| 項目 | 備考 |
|---|---|
| 事業場ID / 名称 / 郵便番号 / 所在地 / 電話番号 | |
| 業種コード | 表1(日本標準産業分類・中分類)から1つ |
| 集約フラグ | 建設現場等「都内各工事現場(八王子市を除く)」の扱い(マニュアル p.8) |
| 提出先区分 | 東京都 / 八王子市 / 他自治体(所在地により提出先が異なるため) |

#### 「業種マスター」(表1ベース)

コード(A01〜S98)と名称。事業場マスターの入力規則(プルダウン)用。マニュアル p.11 の「間違いの多い業種」を備考として持たせる。

#### 「設定」シート

報告者情報(①: 法人名・代表者名・住所・電話)、担当者名・連絡先(余白記入用。マニュアル p.7)、Drive保管フォルダID、AIモデル名等。**APIキーはシートに置かず、GASのスクリプトプロパティに保存する。**

### 3.3 出力シート

#### 「報告書」(様式第三号レイアウト)

生成のたびに年度・事業場単位で作成。ヘッダー(報告者・事業場・業種)+明細行(④〜⑫、番号付き)。1ページ目は様式第三号、行が多い場合は「東京都作成様式(2ページ目以降用)」の列構成(マニュアル p.7)で継続。総ページ/現在ページも出力。印刷・PDF出力してそのまま郵送または電子申請サービス(LoGoフォーム)への転記に使える体裁とする。

## 4. GAS Webアプリ設計

### 4.1 構成ファイル

```
appsscript.json      … スコープ・Webアプリ設定
Code.gs              … doGet、ルーティング
Upload.gs            … Drive保存、取込ログ
Extract.gs           … 生成AI API呼び出し、JSONパース
Normalize.gs         … マスター照合、表記ゆれ、単位換算、重複検知
Ledger.gs            … 台帳CRUD
Report.gs            … 年度集計、様式第三号生成
index.html           … SPA(アップロード/確認/台帳/報告書の4画面)
```

### 4.2 画面

1. **アップロード画面**: 複数PDF選択、進捗表示。1ファイルずつ順次処理(GASの実行時間6分制限対策として、クライアント側から1ファイル=1リクエストで直列に呼び出す)。
2. **確認・修正画面**: 左にPDFプレビュー(Driveプレビュー埋め込み)、右に抽出結果フォーム。
   - マスター照合OK → 緑、あいまい一致 → 黄(候補から選択)、不一致 → 赤(手動選択必須)
   - 単位がt以外の場合は換算式(記載値 × 係数 = t)を明示
   - 「確定して保存」で台帳へ
3. **台帳画面**: 年度・事業場・ステータスでフィルタ、行の再編集、除外(誤取込)。
4. **報告書画面**: 年度・事業場を選択 → 集計プレビュー(④⑧⑨⑪グルーピング、⑤合計、⑥枚数) → 「報告書シート生成」。電子マニフェスト分が混入していないかの注意喚起を表示。

### 4.3 生成AI API連携

- `UrlFetchApp.fetch()` でPDFをbase64同梱しJSON POST。社内APIの仕様(エンドポイント・認証ヘッダー・PDF/画像どちらを受けるか)は要確認。PDF非対応の場合はDriveのサムネイルAPI等で画像化して送る方式に切り替え。
- プロンプトは**JSONスキーマ指定の構造化出力**とし、以下を返させる:
  - 交付年月日、交付番号、事業場名・住所
  - 種類欄でチェックされている廃棄物コードの**全リスト**(混合判定のため)と括弧書き詳細
  - 数量と単位(記載のまま。換算はGAS側で実施)
  - 運搬受託者名・許可番号、運搬先事業場名・住所、処分受託者名・許可番号
  - 各項目の確信度(low/medium/high)…確認画面の警告表示に使用
- **換算・許可番号の決定はAIに任せない。** AIは「読み取り」専任、計算・照合はGASの決定的ロジックで行う(再現性と説明可能性のため)。

### 4.4 セキュリティ・運用

- Webアプリ公開範囲: 「組織内のユーザーのみ」。実行ユーザーは「アクセスしているユーザー」とし、閲覧者のGoogleアカウントを確認者として記録。
- APIキー: スクリプトプロパティ。コード・シートに書かない。
- スプレッドシートの同時書き込みは `LockService` で排他制御。
- 台帳の直接編集は原則Webアプリ経由(シート保護+編集はスクリプトで)。

## 6. 実装フェーズ案

1. **フェーズ1**: スプレッドシート雛形(全シート)+マスター整備
