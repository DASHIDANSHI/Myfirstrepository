# マニフェストPDF抽出・蓄積ツール 設計書

産業廃棄物管理票(紙マニフェスト)のPDFから生成AIで情報を抽出し、Googleスプレッドシートにデータベースとして蓄積するツールの設計書。
最終目的は、東京都「産業廃棄物管理票交付等状況報告書」(様式第三号)の作成を簡易化すること。

- 基盤: Google Apps Script (GAS) Webアプリ
- 参照資料: 東京都環境局「産業廃棄物管理票交付等状況報告書 作成マニュアル(東京都版)」令和8年4月(全23ページ版)

---

## 1. 東京都マニュアルから導かれる要件

設計の前提として、マニュアルの以下のポイントをシステム要件に反映する。

### 1.1 報告制度の要点(マニュアル p.3, Q&A)

| 項目 | 内容 | システムへの反映 |
|---|---|---|
| 報告頻度 | 年1回。前年度(4/1〜3/31)交付分を6/30までに報告。年度は**交付した年度**(Q5) | 「交付年月日」から**年度を自動判定**し、年度単位で集計できること |
| 報告対象 | 紙マニフェストを交付した排出事業者。電子マニフェスト分は報告不要。排出量0の年度は提出不要(Q1) | 本ツールの対象は**紙マニフェストのみ**(電子分はJWNETが報告) |
| とりまとめ | **事業場(排出場所の住所)ごと**に報告書を作成。店舗が100あれば100通(Q6)。建設現場は「都内各工事現場(八王子市を除く)」として1事業場にまとめ可(現場ごとも可、Q7)。移転時は移転前後で別報告書(Q8)、合併時は旧社・新社別(Q12) | **事業場マスター**を持ち、レコードごとに事業場を紐付ける |
| 二次マニフェスト | 中間処理業者の二次マニフェストも報告対象(Q20)。④⑧⑨⑪が同一なら一次と合算可(Q21) | 台帳に一次/二次の区分列を持つ(中間処理業を営む場合のみ使用) |
| 様式 | 独自様式は不可。行数の増減・枠サイズ調整のみ可(Q9) | 出力は様式第三号のレイアウトを踏襲する |
| 未提出リスク | 勧告→公表→命令→罰則(1年以下の拘禁又は100万円以下の罰金、Q23) | 提出期限(6/30)のリマインド機能を推奨 |

### 1.2 報告書の記載項目(マニュアル p.6〜10 の①〜⑫)

抽出・蓄積すべきデータ項目は、報告書様式の項目に対応させる。

| # | 報告書項目 | マニフェストA票上の位置 | 記載ルール(マニュアルより) |
|---|---|---|---|
| ① | 報告者(住所・氏名・電話) | 排出事業者欄 | 法人名+代表者名(契約権限の委譲があれば支店長等でも可、Q10)。押印不要 → **設定シートから取得(PDF抽出不要)** |
| ② | 事業場の名称・所在地・電話 | 事業場(排出事業場)欄 | マニフェスト記載のとおり → **事業場マスターと照合**。電話が無い事業場は報告書記載者の連絡先(Q13) |
| ③ | 業種 | (記載なし) | 表1(日本標準産業分類・中分類)から1つ → **事業場マスターに保持** |
| ④ | 産業廃棄物の種類 | 種類チェック欄 | 表2から1つ(**省略表記でも可**)。詳細は括弧書き。複数チェックは混合廃棄物(42)〜(50)、(71)から選択+種類内訳を括弧書き。**水銀使用製品産業廃棄物は括弧書き不要**(p.15注) |
| ⑤ | 排出量(t) | 数量欄 | t以外(m³, kg, ℓ)は**表3の換算式でトンに換算**。小数第7位を四捨五入し6桁まで。1g未満は「0.000001t」(Q15) |
| ⑥ | 管理票の交付枚数 | ― | **A票の枚数**をカウント |
| ⑦ | 運搬受託者の許可番号 | 運搬受託者欄 | **下6桁**(全国共通)。自社運搬は**空欄** → マスターから取得 |
| ⑧ | 運搬受託者の氏名又は名称 | 運搬受託者欄 | 自社運搬は「自社運搬」。個人事業主は許可証記載の名称 |
| ⑨ | 運搬先の住所 | 運搬先の事業場(処分事業場)欄 | マニフェスト記載の住所。積替保管を経由しても**運搬受託者が1社なら積替保管住所の記載は不要**(Q17) |
| ⑩ | 処分受託者の許可番号 | 処分受託者欄 | **下6桁**。自治体は**空欄**。有償売却は「有償売却」。再生事業者は「再生事業者番号」。大臣認定は認定番号 → マスターから取得 |
| ⑪ | 処分受託者の氏名又は名称 | 処分受託者欄 | 自社施設間移動は「自社施設」 |
| ⑫ | 処分場所の住所 | 運搬先の事業場欄 | 通常は⑨と同一のため記入不要(Q16) |

### 1.3 集計ルール(マニュアル p.6, p.9)

> **④種類・⑧運搬受託者・⑨運搬先・⑪処分受託者の全てが同じ**マニフェストについて、排出量の合計とマニフェスト枚数を1行に記載する。1つでも異なれば別の行に分ける。

→ **DBはマニフェスト1枚=1レコードで蓄積し、報告書生成時に上記4キーでグルーピング集計する。** 蓄積段階で合算しないことで、元データへの遡及・修正・監査が可能になる。

### 1.4 特殊ケース(マニュアル p.7 記載例、p.9〜10)

以下のケースを「特殊区分」としてデータモデルに持たせる。

| ケース | ⑦⑩許可番号欄 | ⑧⑪名称欄 |
|---|---|---|
| 自社運搬 | ⑦空欄 | ⑧「自社運搬」 |
| 処分受託者が自治体(東京都、清掃一部事務組合等) | ⑩空欄 | 自治体名 |
| 有償売却(逆有償で運搬部分のみ廃棄物扱い) | ⑩「有償売却」 | 売却先業者名 |
| 自社施設間の移動(処分委託なし) | ⑩空欄 | ⑪「自社施設」 |
| 再生事業者への委託 | ⑩「再生事業者番号」 | 業者名 |
| 大臣認定業者 | ⑩「大臣認定 平成◯年第◯号」 | 業者名 |

### 1.5 1枚のマニフェストが報告書の複数行になるケース(Q18・Q19)

**区間委託(リレー運搬)**: 複数の収集運搬業者が区間ごとに運搬した場合、**区間ごとに1行**記載する。

- 区間1の行: 種類・排出量・枚数・運搬業者(区間1)・運搬先(積替保管施設)を記載。処分欄は空欄
- 中間区間の行: 種類・排出量・枚数は空欄(番号1の報告のため)。運搬業者と運搬先のみ
- 最終区間の行: 運搬業者(最終区間)・運搬先(処分事業場)・処分受託者を記載

**再委託**: 収集運搬の再委託は「A社(再委託)」の行+B社の行の2行。処分の再委託も同様に「E社(再委託)」+F社の2行。

→ **台帳は「1マニフェスト×1運搬区間=1行」を最小単位とする**(通常のマニフェストは区間1のみの1行)。同一マニフェストの区間行は交付番号+区間番号で紐付け、報告書生成時にQ18のレイアウトを再現する。

### 1.6 廃棄物種類の判定ルール(表2、参考1・2、Q14)

- 種類コードは(1)〜(50)産業廃棄物+(51)〜(71)特別管理産業廃棄物の71種。**省略表記**(廃プラ、ガラ陶、アスコン等)での記入も可
- カテゴリ: 通常(1)〜(22) / 石綿含有(23)〜(30) / 水銀使用製品(31)〜(35) / 水銀含有ばいじん等(36)〜(41) / 混合(42)〜(50) / 特管(51)〜(71)
- **間違いの多い判定(参考1)** → 確認画面で警告表示する:
  - 廃タイヤ(合成ゴム)は「ゴムくず」ではなく**廃プラスチック類**(ゴムくずは天然ゴムのみ)
  - 廃石膏ボードは「がれき類」ではなく**ガラス・コンクリート・陶磁器くず**
  - コンクリート破片は、工事由来なら**がれき類**、製造過程由来なら**ガラ陶**
  - 引火性廃油(有害)・強廃酸(有害)・強廃アルカリ(有害)を廃油(有害)等と混同しない
- **混合廃棄物の具体例(参考2)** → マッピング辞書に登録:
  - 電話機・パソコン・自動販売機 → (47)廃電気機械器具
  - 金属製の机・イス → (50)その他混合廃棄物
  - 乾電池: 水銀なし → (48)廃電池類、水銀あり → (31)電池類(水銀使用製品)
  - 蛍光灯: 水銀なし → (47)廃電気機械器具、水銀あり → (32)蛍光灯・水銀ランプ
- **建設系廃棄物マニフェストのコード読み替え(Q14)** → 変換マスターを持つ。**運用上、全国連A票と建設系マニフェストの混在が確定しているため、様式判別とこの読み替えは必須機能**:

| 建設系マニフェストの記載 | 報告書の種類(表2) |
|---|---|
| 03 その他がれき類 | (16) がれき類 |
| 07 混合(安定型のみ) | (43) 建設混合廃棄物(安定型のみ) |
| 11 建設汚泥 | (2) 汚泥 |
| 15 廃石膏ボード | (14) ガラス・コンクリート・陶磁器くず |
| 16 混合(管理型含む) | (44) 建設混合廃棄物(管理型を含む) |
| 08・17 石綿含有産業廃棄物 | (23)〜(30) 石綿含有(品目チェック欄で特定) |

### 1.7 トン換算ルール(表3、p.16)

- 換算式:
  - 重量(t) = 体積(m³) × 換算係数(t/m³)
  - 重量(t) = 重量(kg) ÷ 1,000
  - 重量(t) = (容積(ℓ) ÷ 1,000) × 換算係数(t/m³)
- **自社で算出した換算係数があればそちらを優先**(表3は環境省の参考値)
- 混合廃棄物は**種類ごとにあん分してから各換算係数を適用し、合計**する(例: 混合90m³ = 廃プラ60m³×0.35 + ガラ陶30m³×1.00 = 51.0t)
- 蛍光灯・電話機・ロッカー等が**台数**で記載されている場合は、処理業者やメーカーHP等で重量を確認する → 換算不能として確認画面で手入力を促す
- 丸め: 小数第7位を四捨五入して6桁。1g未満は「0.000001t」(Q15)

### 1.8 混合廃棄物の処理フロー(詳細設計)

マニフェストの種類欄に**複数の種類がチェックされている場合**のフロー。ルールはマニュアル p.8(記入方法④)、p.15(参考2)、p.16(表3の注記)に分散しているため、ここで一本化する。

#### Step 1: 検知(AI抽出)

AIは「混合かどうか」を判定せず、**チェックされている種類の全リスト**と、品名(産業廃棄物の名称欄。例: 蛍光灯、電話機)、水銀・石綿・有害物質に関する記載の有無をそのまま返す。判定は次のStep 2でGASの決定的ロジックが行う。

#### Step 2: 報告用コードの判定(GASロジック・優先順)

チェックが1つだけなら通常フロー(その種類コード)。複数チェックの場合は以下の優先順で候補コードを決定する。**最終確定は必ず確認画面で人が行う**(候補と判定根拠を表示)。

| 優先 | 条件 | 報告用コード | 括弧書き |
|---|---|---|---|
| 1 | 水銀使用製品に該当(品名が蛍光灯・乾電池・水銀ランプ等+水銀の記載) | (31)〜(35) | **不要**(p.15注) |
| 2 | 石綿含有の記載あり | (23)〜(30)の該当種類(混合なら(23)建設混合(石綿含有)) | 必要 |
| 3 | 特別管理産業廃棄物のチェックを含む | (71)その他特別管理産業廃棄物 | 必要 |
| 4 | 建設系マニフェストの混合コード | 変換マスター適用: 07→(43)、16→(44) | 必要 |
| 5 | 品目辞書に一致(参考2): 電話機・パソコン・自動販売機・蛍光灯(水銀なし)→(47) / 乾電池(水銀なし)→(48) / シュレッダーダスト→(45) / 廃自動車→(46) / 複合材→(49) | 該当コード | 必要 |
| 6 | 上記のいずれにも該当しない | (50)その他混合廃棄物 | 必要 |

**括弧書きはシステムが自動生成する**: チェックされた種類を表2コードの昇順で「(廃プラスチック類、金属くず)」の形式に整形(省略表記の選択可)。自由文の手入力にしないのは、④が集計キーであり表記が揺れると報告書の行が割れるため。

#### Step 3: 排出量のトン換算

| 記載単位 | 換算方法 |
|---|---|
| t | そのまま(あん分不要) |
| kg | ÷1,000(あん分不要。係数を使わないため) |
| m³ / ℓ で、選択コードが表3に係数を持つ((42)〜(44)建設混合0.26、(47)廃電気機械器具1.00 等) | その係数で直接換算 |
| m³ / ℓ で、係数がない((45)(46)(48)(49)(50)(71)) | **内訳あん分方式**(下記) |
| 台数等 | 換算不能。処理業者・メーカーHP等で重量を確認して手入力(p.16注) |

**内訳あん分方式**(表3注記の例: 混合90m³ = 廃プラ60m³×0.35 + ガラ陶30m³×1.00 = 51.0t):

1. 内訳種類ごとの数量を取得(マニフェストに内訳記載があればAI読取値、なければ**確認画面でユーザーが入力**)
2. 内訳数量の合計 = 総量 であることを検算(不一致なら警告)
3. 各内訳 × 各種類の換算係数 → 小計、その合計を排出量(t)とする(小数6桁丸めは合計に対して適用)

#### Step 4: 台帳保存

- 台帳は1行(廃棄物コード=判定した混合コード、詳細=自動生成した括弧書き)
- あん分した場合は**内訳(種類・数量・係数・小計)を「あん分内訳」列にJSONで保存**し、後から計算根拠を追跡できるようにする

#### Step 5: 集計・出力

- ④の集計キーは「報告用コード+括弧書き」の組。括弧書きが自動生成で安定しているため、同じ内訳の混合廃棄物は正しく1行に合算される
- グリッド出力のセル値は「その他混合廃棄物(廃プラスチック類、ガラス・コンクリート・陶磁器くず)」形式(水銀使用製品は括弧なし)

#### 運用上の注意(確認画面に表示)

- マニフェストは本来**種類ごとに交付が義務**(法施行規則第8条の20第1号)。排出段階で一体不可分の場合のみ1枚にまとめられる。**分別可能なもの(ビン・缶・ペットボトル等)が混合で交付されているのを検知したら、種類ごとの交付への運用見直しを促す注意を表示**(p.15の重要枠)

### 1.9 他道府県・政令市への報告対応(マルチ自治体設計)

本ツールは東京都以外の自治体への報告にも使用する。設計の考え方は次のとおり。

**全国共通の部分(= 本設計の中核はそのまま使える)**

- 報告義務の根拠は廃棄物処理法第12条の3第7項で**全国共通**。様式第三号も**国の省令様式**であり、報告項目①〜⑫・提出期限(6/30)・年度の考え方は全国同じ
- 廃棄物の種類(表2のベースとなる法定区分)、換算係数(環境省が平成18年12月27日に示した参考値)、業種分類(日本標準産業分類)も全国共通
- したがって**台帳のデータモデル・AI抽出・マスター照合・トン換算・④⑧⑨⑪集計ロジックは自治体に依存しない**

**自治体ごとに異なる部分(= 「自治体プロファイル」として外出しする)**

| 差分項目 | 例 |
|---|---|
| 提出先 | 事業場所在地の都道府県又は政令市。**産廃事務が移譲された市**(東京都でいう八王子市)は市に提出 |
| 提出方法 | 郵送 / 窓口 / 電子申請(東京都はLoGoフォーム。自治体により電子申請の有無・URLが異なる) |
| 継続様式 | 2ページ目以降の独自様式(東京都作成様式など)。無い自治体は様式第三号を複製 |
| 記入要領の細部 | 有償売却・自社運搬等の特殊ケースの書き方、混合廃棄物の内訳表記などのローカルルール |
| 換算係数 | 基本は環境省参考値だが、自治体が独自値を示す場合はオーバーライド |

**実装方針**

1. **自治体マスター**(3.2参照)を新設し、事業場マスターの「提出先区分」を自治体マスター参照に置き換える。**自治体の登録はユーザー自身がWebアプリの設定画面から行う**(開発側で全国分を事前整備しない)。必須項目は自治体名のみで、提出先住所・提出方法・列マッピング等はすべて任意(未設定ならデフォルト=国様式で動作)
2. 提出先の決定: **ユーザーが事業場ごとに提出先自治体をプルダウンで選択**する。所在地からの自動判定(政令市・中核市など産廃事務移譲市の考慮)は補助機能とし、判定できない場合もユーザー選択で運用できる
3. **アウトプットは様式のレイアウト再現ではなく、各自治体の提出様式(Excel等)へコピペできる行列グリッド**(3.3参照)。列の並び順・空欄ルールを自治体プロファイルの「列マッピング」で定義し、**デフォルトは国の様式第三号の明細列順(④〜⑫)**とする。未登録の自治体でもデフォルトでまず出力できる
4. 記入要領のローカルルールはプロファイルの「注意事項」として報告書画面に表示し、確認者が判断できるようにする

> 東京都マニュアルをベースに実装した記載ルール(1.2〜1.7)は国様式の解釈として概ね全国で通用するが、**特殊ケースの表記(有償売却等)は自治体により指示が異なることがある**ため、実際に報告する自治体のマニュアル・記入要領を入手してプロファイル化することを前提とする。

### 処理フロー

1. **アップロード**: ユーザーがWebアプリでPDFを選択(複数可)。GASがDriveの保管フォルダに保存。
2. **AI抽出**: PDFをbase64化して社内生成AI APIへ送信。JSONスキーマを指定した構造化出力で、マニフェストの記載項目(交付番号、交付年月日、事業場、廃棄物種類チェック、数量+単位、運搬受託者(区間1〜3)、積替保管、運搬先、処分受託者 等)を抽出。**全国連A票か建設系マニフェストかの様式判別**も行う。
3. **正規化・照合**(GAS側ロジック):
   - 業者名をマスターと照合(法人格除去等の正規化一致→あいまい一致→学習別名辞書の3段階。3.2参照) → **許可番号下6桁をマスターから取得**(AIにPDFの許可番号を読ませるのは補助とし、正はマスター)
   - 廃棄物種類を表2コードにマッピング。建設系様式は変換マスターで読み替え。複数チェック時は混合廃棄物+括弧書き(水銀使用製品は括弧書きなし)
   - 数量をトンに換算(1.7のルール)。元の数量・単位も保持
   - 交付番号による重複チェック、必須項目・値域チェック、参考1の誤りやすいパターン警告
4. **確認・修正**: 抽出結果を編集可能なフォームで表示(PDFプレビュー併置)。照合に失敗した項目・信頼度の低い項目は警告表示。ユーザーが修正して確定。
5. **保存**: マニフェスト台帳に追記(通常1枚=1行、区間委託・再委託は複数行)。ステータス「確認済」。
6. **報告書生成**: 年度と事業場を指定 → ④⑧⑨⑪でグルーピング集計 → **各自治体の提出様式(Excel等)へそのまま貼り付けられる行列グリッド**を生成(3.3参照)。様式レイアウトの再現はしない。

> **設計方針: AIの抽出は必ず人間の確認を挟む。** 行政報告の元データであるため、全自動保存はしない。確認画面での修正内容はログに残す。

### 3.2 マスターシート

#### 「収集運搬業者マスター」「処分業者マスター」(産廃情報ネットから入手・列構造は共通)

| 項目 | 備考 |
|---|---|
| 業者名 | 許可証記載の名称(個人事業主対応。マニュアル p.9) |
| 所在地 | |
| 固有番号(6桁) | **報告書⑦⑩に記載する「許可番号の下6桁」そのもの**(全国共通・業者単位)。業者の名寄せキーとして使用 |
| 許可番号 | 全桁 |
| 許可主体 | 許可を出した都道府県・政令市。同一業者が複数の許可を持つ場合は許可ごとに1行になる |
| 業の区分 | 収集運搬(積替保管の有無)/ 中間処理 / 最終処分 等 |
| 許可年月日 / 許可期限年月日 | **期限切れ・期限間近の警告表示に使用** |
| 優良認定の有無 | 参考情報として台帳・確認画面に表示可 |

運用ルール:

- 産廃情報ネットからのエクスポートを**そのまま貼り付けて再取込できるよう、このシート自体には列を追加しない**
- 同一業者の複数許可行は固有番号で名寄せする
- 自社運搬・自治体・有償売却先・再生事業者・大臣認定など**産廃情報ネットに載らない相手先**は業者補足シート側に登録し、特殊区分と許可番号代替表記(「有償売却」「再生事業者第◯号」等)を持たせる

**業者名の照合ロジック(3段階)**

表記ゆれは人手の別名リストではなく、**正規化による機械照合を第一手段**とする。

1. **正規化一致**(これで大半を確定・メンテ不要): AI読取名とマスター業者名の双方から法人格(株式会社/有限会社/合同会社/(株)/(有)/㈱/㈲ 等)を除去し、全角半角・スペース・中黒・カナ表記を統一した「正規化名」で完全一致 → 固有番号を確定
   - ※ 法人格は照合キーから外すだけで**捨てない**。「㈱サトウ」と「㈲サトウ」のような別会社の衝突がありうるため、正規化名が同一の業者がマスターに複数いる場合は自動確定せず必ず候補提示に落とす(法人格は候補の並び順のスコアに使う)
2. **あいまい一致**(候補提示): 正規化名同士の類似度(編集距離等)で候補を提示し、確認画面で人が選択。OCR誤読(「クリーン」→「クリーソ」等)はここで拾う
3. **学習別名辞書**(自動蓄積・事前整備しない): 正規化では原理的に一致しないケース — **社名変更**(旧社名のマニフェスト)、**屋号と許可名義の不一致**(個人事業主。マニュアル p.9)、グループ会社の通称 — は、人が確認画面で紐付けた「読取名→固有番号」の組を自動記録し、次回から自動一致させる(運搬先辞書と同じ方式)

| 許可番号代替表記 | ⑩欄の記載ルール対応 |

| 項目 | 備考 |

| 固有番号(6桁) | 紐付け先の業者 |
| 登録日時 / 登録者 | 監査用 |

#### 「運搬先辞書」(自動生成・事前準備不要)

⑨運搬先住所の「正」はマニフェスト記載値であり、**転記のためのマスター照合は不要**(台帳に読み取りテキストを保存すれば足りる)。ただし⑨は**④⑧⑨⑪集計のグルーピングキー**であるため、同一運搬先の表記ゆれ・OCR誤読(「3-2-1」と「3丁目2番1号」等)があると報告書の行が不当に分かれる。

そこで事前整備するマスターは持たず、**確認済みレコードから自動的に育つ辞書**とする:

- 人が確認画面で確定した「処分業者(固有番号)×運搬先住所」の組を自動登録
- 以後の取込で同一業者の近似住所を検知したら、**確定済み表記への統一を候補提示**(強制はしない。マニフェスト記載が実際に異なる場合もあるため)
- 積替保管施設(Q17・Q18)の住所も同様に蓄積

### 3.3 出力シート

#### 「報告書データ」(コピペ用の行列グリッド)

**本システムのアウトプットは、各自治体が配布する提出様式(Excel等)へそのまま貼り付けられる行列構造のデータ**とする。様式のレイアウト(枠線・押印欄・ページ割り)はアプリでは再現せず、提出様式側に任せる。生成のたびに年度・事業場単位で新規シートを作成する。

**グリッドの構成(2ブロック)**

1. **ヘッダーブロック**(縦持ちのキー・値ペア): 実績年度 / 報告者住所・氏名・電話 / 事業場名称・所在地・電話 / 業種コード・名称 / 担当者名・連絡先。様式のヘッダー欄へ項目ごとに貼り付ける
2. **明細ブロック**(1行=様式の明細1行): 列順はデフォルトで国様式第三号のとおり

| 番号 | 産業廃棄物の種類 | 排出量(t) | 管理票の交付枚数 | 運搬受託者の許可番号 | 運搬受託者の氏名又は名称 | 運搬先の住所 | 処分受託者の許可番号 | 処分受託者の氏名又は名称 | 処分場所の住所 |
|---|---|---|---|---|---|---|---|---|---|

**セル値は「貼り付ければ完成」の状態まで整形済み**とする:

- 集計適用済み: ④⑧⑨⑪の4キーでグルーピング、⑤排出量合計(小数6桁丸め)・⑥枚数カウント。一次・二次マニフェストは4キーが同じなら合算(Q21)
- 空欄ルール適用済み: 自社運搬の⑦、自治体処分の⑩、通常の⑫などは空セル
- 特殊表記適用済み: 「自社運搬」「有償売却」「再生事業者第◯号」、種類の括弧書き(水銀使用製品は括弧書きなし)等
- 区間委託・再委託はQ18・Q19の複数行構造(中間行の空欄含む)をグリッドの行としてそのまま出力
- **許可番号は先頭ゼロ保持のため文字列として出力**(Excel貼り付け時の欠落防止)
- 列順・省略列は自治体プロファイルの列マッピングで切替(デフォルト=国様式)

**出力手段**

- スプレッドシート上のグリッド(範囲選択してコピー)
- Webアプリの「クリップボードにコピー」ボタン(TSV形式。Excelにそのまま貼り付け可)
- 必要に応じてExcel(.xlsx)ダウンロード

**運用上の注意(画面に表示)**

- 自治体のExcel様式にプルダウン(入力規則)が設定されている場合は、**解除してから貼り付ける**(マニュアル p.9 の操作手順を注記として表示)
- 提出後の訂正は「再提出」朱書き+訂正内容書類が必要(Q25)なので、**生成した報告書データのスナップショットを版管理**し、差分を出せるようにする

## 4. GAS Webアプリ設計

### 4.1 構成ファイル

```
appsscript.json      … スコープ・Webアプリ設定
Code.gs              … doGet、ルーティング
Upload.gs            … Drive保存、取込ログ
Extract.gs           … 生成AI API呼び出し、JSONパース
Normalize.gs         … マスター照合(正規化・あいまい一致・学習辞書)、単位換算、重複検知
Ledger.gs            … 台帳CRUD
Report.gs            … 年度集計、様式第三号生成
index.html           … SPA(アップロード/確認/台帳/報告書/設定の5画面)
```

### 4.2 画面

1. **アップロード画面**: 複数PDF選択、進捗表示。1ファイルずつ順次処理(GASの実行時間6分制限対策として、クライアント側から1ファイル=1リクエストで直列に呼び出す)。
2. **確認・修正画面**: 左にPDFプレビュー(Driveプレビュー埋め込み)、右に抽出結果フォーム。
   - マスター照合OK → 緑、あいまい一致 → 黄(候補から選択)、不一致 → 赤(手動選択必須)
   - 単位がt以外の場合は換算式(記載値 × 係数 = t)を明示。台数記載は手入力を促す
   - 複数チェック(混合)の場合は判定候補コードと根拠を表示し、あん分が必要なら内訳数量の入力欄を展開(合計=総量の検算つき)。分別可能な品目の混合を検知したら運用見直しの注意を表示(1.8参照)
   - 参考1の誤りやすいパターン(廃タイヤ→廃プラ等)に該当したら注意書きを表示
   - 積替保管欄に記載があり運搬受託者が2社以上の場合は区間行の入力UIを展開(Q17・Q18)
   - 建設系マニフェストの場合は種類コードの読み替え結果(1.6)を「建設系コード◯◯ → 表2(◯◯)」の形で明示。事業場欄は工事名称・現場住所になるため、事業場マスター(集約事業場「都内各工事現場」等)への紐付けを確認させる
   - 「確定して保存」で台帳へ
3. **台帳画面**: 年度・事業場・ステータスでフィルタ、行の再編集、除外(誤取込)。
4. **報告書画面**: 年度・事業場を選択 → 提出先自治体と提出方法を表示 → 集計プレビュー(④⑧⑨⑪グルーピング、⑤合計、⑥枚数) → 「グリッド生成」「クリップボードにコピー(TSV)」「Excelダウンロード」。電子マニフェスト分が混入していないかの注意喚起、自治体プロファイルのローカル記入ルール、貼り付け前のプルダウン解除手順(未入手自治体はデフォルト列順である旨の警告)を表示。
5. **設定・マスター管理画面**: 報告者情報の編集、事業場の登録・編集(提出先自治体の選択を含む)、**自治体の登録・編集**(必須は名称のみ。提出先住所・宛名、提出方法、列マッピング、注意事項は任意)。業者マスターの再取込(産廃情報ネットのエクスポート貼り付け)への導線もここに置く。

### 4.3 生成AI API連携

- `UrlFetchApp.fetch()` でPDFをbase64同梱しJSON POST。社内APIの仕様(エンドポイント・認証ヘッダー・PDF/画像どちらを受けるか)は要確認。PDF非対応の場合はDriveのサムネイルAPI等で画像化して送る方式に切り替え。
- プロンプトは**JSONスキーマ指定の構造化出力**とし、以下を返させる:
  - 様式の判別(全国産業廃棄物連合会A票 / 建設系廃棄物マニフェスト / その他)。**両様式の混在運用が前提**のため、プロンプトには両様式のフィールド配置を記載し、様式ごとの読み取り例(few-shot)を用意する。判別結果は台帳のAI生データに保持し、建設系の場合は種類コードに変換マスター(1.6)を適用する
  - 交付年月日、交付番号、事業場名・住所
  - 種類欄でチェックされている廃棄物コードの**全リスト**(混合判定のため)と括弧書き詳細、有害物質・水銀・石綿の記載有無
  - 数量と単位(記載のまま。換算はGAS側で実施)
  - 運搬受託者名・許可番号(区間1〜3)、積替保管欄の名称・住所、運搬先事業場名・住所、処分受託者名・許可番号
  - 各項目の確信度(low/medium/high)…確認画面の警告表示に使用
- **換算・許可番号・種類コードの決定はAIに任せない。** AIは「読み取り」専任、計算・照合・読み替え(建設系変換、混合判定、水銀/石綿分岐)はGASの決定的ロジックで行う(再現性と説明可能性のため)。

### 4.4 セキュリティ・運用

- Webアプリ公開範囲: 「組織内のユーザーのみ」。実行ユーザーは「アクセスしているユーザー」とし、閲覧者のGoogleアカウントを確認者として記録。
- APIキー: スクリプトプロパティ。コード・シートに書かない。
- スプレッドシートの同時書き込みは `LockService` で排他制御。
- 台帳の直接編集は原則Webアプリ経由(シート保護+編集はスクリプトで)。
- 毎年4月に「6/30までに前年度分を提出」のリマインドを時間主導トリガーで通知(推奨)。
